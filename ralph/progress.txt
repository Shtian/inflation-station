## Codebase Patterns
- Keep deterministic category color API shape stable even when changing color spaces (`hue`, `saturation`, `lightness`, and contrast fields), and adapt internals for conversion/contrast math.
- Keep `uncategorized` category color as an explicit neutral fallback in `src/lib/category-color.ts`, and provide separate light/dark text tokens to preserve readability in badges.
- Inline success feedback is commonly state-driven (`notice`/`success`/`submitNotice`) in route manager hooks, and Playwright coverage usually asserts those exact strings with `getByText(...)`; toast migrations should update both surfaces together.
- Mount the Sonner toaster once in `src/app/layout.tsx` via a shared `src/components/ui/sonner.tsx` wrapper so route-level toast migrations only call `toast(...)` and never create extra toaster instances.
