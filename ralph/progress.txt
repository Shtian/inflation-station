## Codebase Patterns
- Keep cross-route navigation in `src/app/layout.tsx` so route-level pages can be introduced incrementally without duplicating nav markup.
- During route-split migrations, keep `/` as a temporary legacy workspace and document transitional routing behavior in `README.md`.
- Keep overview analytics filter state and `/api/dashboard/analytics` fetching logic scoped to the `/overview` route UI instead of the legacy `/` workspace.
- Keep account CRUD interactions and success/error notices inside `src/app/accounts/*`, and let other routes only consume `/api/accounts` for account selection needs.
- Keep category and category-rule CRUD UI/state scoped to `src/app/categories/*`, with dedicated `/api/categories` and `/api/category-rules` handlers for deterministic rule management.
- Keep the `/import` route wired to `/api/imports/parse` for parse feedback and staging, with transaction persistence deferred to explicit review submit.
- Keep import review staging in dedicated Prisma models (`ImportReviewSession`, `ImportReviewRow`) and return staged row ids in parse responses so later review edits stay decoupled from persisted `Transaction` rows.
- Persist import-review transactions only from `/api/imports/submit` using staged `sessionId` + row-level category decisions, and delete the session after submit so abandoned reviews never write data.
- Run deterministic category-rule matching during import staging and persist prefilled `ImportReviewRow.categoryId`, but degrade gracefully to `null` if suggestion lookup fails.
- Compute potential duplicate warnings for import review rows from the same fingerprint fields as transaction dedupe (`accountId`, `bookingDate`, `amountNok`, `normalizedMerchant`, `paymentType`) and keep flagged rows editable instead of auto-dropping.
- In `/import` review UI, fetch categories from `/api/categories` and allow both global (`accountId: null`) and selected-account categories in row-level category selectors.
