## Codebase Patterns
- Use `prisma.config.ts` for Prisma 7 datasource and migration settings; do not set datasource `url` inside `schema.prisma`.
- Prisma 7 SQLite runtime access requires a driver adapter (`@prisma/adapter-better-sqlite3`) passed into `new PrismaClient({ adapter })`.
- Keep local SQLite database files ignored (`prisma/dev.db`) and commit schema + migrations only.
- Store normalized merchant text and explicit payment type on transactions to keep import dedupe and category-rule matching deterministic.
- For destructive account operations, guard in API handlers and return explicit conflict errors (e.g. `409 ACCOUNT_HAS_TRANSACTIONS`) instead of relying on implicit DB failures.
- Keep CSV import parsing in dedicated `src/lib/import/*` modules that return `rows` and structured row-level `errors` so import diagnostics stay stable as pipeline steps are added.
- Keep import diagnostics as stable count fields (`imported`, `duplicates`, `ignoredReserved`, `invalid`) so parser and endpoint layers can compose without response-shape drift.
- Keep import dedupe logic in a shared helper and align its fingerprint fields with the Prisma `Transaction` uniqueness constraint.
- Canonicalize parsed payment-type labels to Prisma `PaymentType` enum values before dedupe and insert so fingerprints align with stored transactions.
- Apply category rules deterministically (priority first, then merchant-keyword specificity) so suggestion outcomes stay stable across runs.
- Treat unit tests as part of done criteria for testable behavior changes; only skip with an explicit documented blocker.
