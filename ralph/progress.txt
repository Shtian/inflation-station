## Codebase Patterns
- Transactions list query parsing should trim optional text/id filters and normalize empty values to `undefined` before passing to domain modules.
- Keep transactions sorting query strings in `<field>:<direction>` format with an explicit field allowlist and per-param `INVALID_*` HTTP 400 responses.
- For inclusive `dateTo` filtering on `bookingDate`, convert to `< next UTC day` in domain queries to handle non-midnight timestamps safely.
- For server-sorted transaction pagination, always add a deterministic `id` tiebreaker to every `orderBy` mode.
- For route table state sync, keep URL params canonical by replacing legacy aliases (for example `query` -> `globalQuery`) and preserving unrelated query params when writing table state.
- In transactions table migrations, model non-data UI cells (notes/actions) as TanStack `display` columns and use `row.original` for mutation handlers.
- Keep transactions toolbar filter controls controlled by `use-transactions-manager.ts` state (not local component state) so URL sync and page-reset behavior stay consistent.
