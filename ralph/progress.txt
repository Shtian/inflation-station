## Codebase Patterns
- Keep deterministic category color API shape stable even when changing color spaces (`hue`, `saturation`, `lightness`, and contrast fields), and adapt internals for conversion/contrast math.
- Keep `uncategorized` category color as an explicit neutral fallback in `src/lib/category-color.ts`, and provide separate light/dark text tokens to preserve readability in badges.
- Inline success feedback is commonly state-driven (`notice`/`success`/`submitNotice`) in route manager hooks, and Playwright coverage usually asserts those exact strings with `getByText(...)`; toast migrations should update both surfaces together.
- Mount the Sonner toaster once in `src/app/layout.tsx` via a shared `src/components/ui/sonner.tsx` wrapper so route-level toast migrations only call `toast(...)` and never create extra toaster instances.
- For Sonner feedback assertions in Playwright, target toast elements with `[data-sonner-toast]` + `hasText` instead of relying on inline banner DOM.
- In provider mappings, keep create on the Server Action (`createImportProviderMappingAction`) while edit/delete continue on `/api/import-provider-mappings/[providerMappingId]`, then refresh table state via `loadMappings()` after successful mutations.
- In the import route, keep successful submit summary feedback in `use-import-workflow.ts` via `toast.success(...)` and keep upload/review phase components focused on inline actionable errors.
- In import settings managers, keep success copy in Sonner toasts and reserve inline alerts for save/load failures so corrective feedback stays visible while confirmations stay transient.
- In monthly review settings, emit save success feedback with Sonner toasts from `settings/monthly-review-settings-manager.tsx` and keep load/save failures as inline alerts.
- During Field primitive migrations, preserve existing form control ids/placeholders so accessible label wiring and E2E selectors remain stable.
- In debounced filter UIs, avoid syncing raw input state from every table-state update; sync from parsed URL state to prevent typed text from being reset by unrelated filter changes.
- For `Select` controls migrated to Field primitives, keep the `SelectTrigger` id and pair it with `FieldLabel htmlFor` to preserve accessible label association and existing selectors.
- For custom combobox-style controls migrated to Field primitives, keep the existing control `id` and pair it with `FieldLabel htmlFor` inside `FieldContent` to preserve a11y label binding and stable selectors.
- For custom badge-input controls migrated to Field primitives, keep Enter-to-add behavior and route validator copy through `FieldError` so inline validation semantics stay accessible and consistent.
- In the transactions edit dialog, keep note character-count and note validation copy inline in the note field area while reserving dialog-level alerts for submit failures.
