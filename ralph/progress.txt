## Codebase Patterns
- For Server Action mutations, keep a typed result union (`ok` + `data` or typed `error`) and centralize Zod-validation/error-shape helpers in `src/lib/server-actions/mutation-result.ts`.
- For Playwright coverage of client-triggered Server Actions, intercept page-path `POST` requests and detect the `next-action` header while allowing `route.fallback()` so the real action protocol remains intact.
- Preserve UX parity during migration by mapping Server Action `error.code`/`error.details` back to the exact route-era user-facing error strings instead of introducing new copy.
- In client managers that call Server Actions, wrap action calls in `try/catch` so protocol/transport failures still clear loading state and surface the existing save-error copy.
