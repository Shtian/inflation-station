## Codebase Patterns
- For replaceable month-scoped AI outputs, model a single row per month with a unique `monthStart` and persisted lifecycle metadata (`status`, `generatedAt`, `errorMessage`, `reviewText`).
- Persist monthly-review system prompt in a singleton table row with a fixed key, and resolve blank/missing prompt text to a default prompt in the backend service layer.
- Keep monthly timeline aggregation in a route-independent service (`src/lib/monthly-review/overview.ts`) that computes spend from negative transactions, includes review-only months, and calculates MoM deltas only when the immediate prior calendar month exists.
- Compose monthly timeline API rows in `src/lib/monthly-review/timeline.ts` so every month includes an explicit review state (`NOT_GENERATED`, `GENERATING`, `GENERATED`, `FAILED`) with review metadata merged onto deterministic overview metrics.
- Build monthly-review AI generation payloads in a dedicated backend service (`src/lib/monthly-review/generation-input.ts`) that validates `monthStart`, resolves prompt fallback centrally, and returns precomputed spend/category/merchant/MoM metrics plus minimal transaction fields.
- For month-level review generation, always persist replace semantics by resetting the month row to `GENERATING` before provider calls and then persisting either `GENERATED` output or `FAILED` with stable unavailable reasons (`key_missing`, `timeout`, `provider_error`).
- For major routes, keep route state orchestration in focused route-local modules and use route-level `loading.tsx` and `error.tsx` with shared fallback primitives.
- For monthly review actions in UI, open a mandatory confirmation AlertDialog before calling `/api/monthly-review/generate`, and use mode-specific copy for first-time generate vs replace/regenerate flows.
- For monthly review timeline cards, pair state badges with explicit state-specific body copy and show generated review text as preview-first content with a user-controlled full-text toggle.
- Keep monthly-review prompt settings behind `/api/monthly-review/system-prompt` with explicit `GET`/`PUT` response shape (`promptText`, `resolvedPrompt`, `usesDefaultPrompt`) so the UI can distinguish saved text from fallback-default usage.
- Keep category pickers wired through the shared `CategoryCombobox` in import review, transaction edit, and category-rule creation flows, and preserve row-specific import accessibility labels (`Category for row N`) for stable Playwright locators.
- Configure `CategoryCombobox` with `showClear` when uncategorized values are valid and keep `autoHighlight` enabled for keyboard-first category selection.
