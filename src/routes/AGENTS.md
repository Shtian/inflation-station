# Routes AGENTS

Load this when adding or changing a page, loader, server function or the app shell in `src/routes`.

These are TanStack Start file routes. Feature UI, hooks and mutation modules live in `src/app/<feature>`; a route file wires them together.

- A page is `createFileRoute` in `src/routes/<path>/index.tsx` (`$param.tsx` for a path param) with `loader`, `head`, `pendingComponent`, `errorComponent` and `component`. Route-private files sit beside it with a `-` prefix (`-server.ts`, `-components/`); those and colocated `*.test.ts` files stay out of the route tree. `src/routeTree.gen.ts` is generated by the build and dev server.
- A loader also runs in the browser during client navigation, so it reaches the database only through a server function: a GET `createServerFn` in the route's `-server.ts` that wraps a `loadX(prisma)` from `src/lib`.
- URL state is parsed in `validateSearch`, and `loaderDeps` passes it to the loader. Search values arrive as plain strings (`parseSearch` in `src/router.tsx`).
- A mutation is a POST `createServerFn` in `-server.ts` that calls the shared mutation in `src/app/actions/*`, which returns the `src/lib/server-actions/mutation-result.ts` contract. Components call it through `useServerFn`, then `await router.invalidate()` so the loaders rerun.
- Each route's pending and error UI lives in `-components/*-route-states.tsx`, built on `RouteError` and `DefaultRoutePending` from `-shell/route-states.tsx`.
- `__root.tsx` mounts the shell once: the sidebar from `-shell/app-sidebar.tsx`, the Sonner `Toaster` (`src/components/ui/sonner.tsx`) and the palette and sidebar boot scripts. Routes use that one toaster.
- JSON endpoints are server routes under `src/routes/api`; see `src/routes/api/AGENTS.md`.
- Avoid duplicate page/card headings and excessive nested bordered cards; for multi-section pages, prefer separators via `src/components/ui/separator.tsx`.
